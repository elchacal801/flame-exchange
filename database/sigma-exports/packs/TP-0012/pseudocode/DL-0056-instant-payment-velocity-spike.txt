# ======================================================================
# FLAME Detection Rule: Instant Payment Velocity Spike Above 30-Day Baseline
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P4
# Threat Paths: TP-0024, TP-0012
#
# Description:
#   Detects a sudden spike in instant payment frequency that significantly
#   exceeds the account's established 30-day baseline. A spike is defined
#   as the current day's instant payment count exceeding 3 standard
#   deviations above the rolling 30-day mean, indicating potential account
#   compromise or mule activity where the account is being drained rapidly.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: transaction_monitoring
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: instant_payment_initiated
#     payment_rail|contains:
#     - ZELLE
#     - FEDNOW
#     - RTP
#     - ACH_SAMEDAY
#   condition: selection | count() by account_id | compare(op=gt, period=30d, stdev=3)
#   timeframe: 1d
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Small business owner processing seasonal surge in vendor payments
#   - Customer making multiple legitimate payments on a move-in day (deposits, utilities, services)
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
