# ======================================================================
# FLAME Detection Rule: Geographic Impossibility Login
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P2
# Threat Paths: TP-0013, TP-0008
#
# Description:
#   Detects login attempts from geographically impossible locations within
#   a short timeframe. When a user authenticates from one country and a
#   second authentication occurs from a distant country within a window
#   that makes physical travel impossible, it strongly indicates credential
#   compromise and concurrent use by an attacker.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type|contains:
#     - login_success
#     - login_attempt
#   timeframe: 60m
#   condition: 'selection | near by user_id | where geo_distance(src.geo_lat, src.geo_lon,
#     dst.geo_lat, dst.geo_lon) > 1000 and time_diff < 60m
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Users employing VPN services that change egress country between sessions
#   - Corporate proxy chains routing through geographically distributed data centers
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
