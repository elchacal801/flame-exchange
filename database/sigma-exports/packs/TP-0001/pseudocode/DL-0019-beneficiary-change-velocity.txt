# ======================================================================
# FLAME Detection Rule: Beneficiary Change Velocity Anomaly
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P3
# Threat Paths: TP-0001, TP-0004, TP-0006
#
# Description:
#   Detects multiple beneficiary additions or modifications on a single
#   account within a short time window. Rapid beneficiary changes are a
#   strong pre-cursor to payment diversion fraud, where an attacker
#   positions new destination accounts before initiating unauthorized
#   wires.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: core_banking
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type:
#     - BENEFICIARY_ADD
#     - BENEFICIARY_MODIFY
#     - BENEFICIARY_DELETE
#   timeframe: 24h
#   condition: selection | count(distinct beneficiary_id) by account_id > 3
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Corporate treasury teams onboarding multiple new vendors during month-end
#   - Business accounts setting up payroll beneficiaries for the first time
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
