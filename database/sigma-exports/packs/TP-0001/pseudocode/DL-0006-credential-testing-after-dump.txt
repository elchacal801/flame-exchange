# ======================================================================
# FLAME Detection Rule: Credential Testing After Dump
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P2
# Threat Paths: TP-0001, TP-0008
#
# Description:
#   Detects rapid credential validation attempts occurring shortly after a
#   credential dump event. After infostealers exfiltrate harvested
#   credentials, threat actors typically run automated validation to
#   identify which stolen credentials are still active, producing a burst
#   of login attempts across multiple banking portals from the attacker's
#   infrastructure.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: login_attempt
#     auth_result|contains:
#     - failure
#     - success
#   timeframe: 15m
#   condition: selection | count(distinct user_id) by source_ip > 10
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Corporate SSO gateways performing health checks against multiple accounts
#   - Automated monitoring systems testing service account connectivity
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
