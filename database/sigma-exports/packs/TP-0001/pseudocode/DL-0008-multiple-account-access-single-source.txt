# ======================================================================
# FLAME Detection Rule: Multiple Account Access from Single Source
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P2
# Threat Paths: TP-0001, TP-0008
#
# Description:
#   Detects multiple distinct banking accounts being accessed from a single
#   device or IP address within a short timeframe. This pattern is
#   consistent with an attacker using stolen credentials from an
#   infostealer dump to sequentially access compromised accounts for
#   reconnaissance or initial positioning before fraudulent transactions.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: login_success
#   timeframe: 1h
#   condition: selection | count(distinct account_id) by source_ip > 5 or selection |
#     count(distinct account_id) by device_fingerprint > 3
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Shared corporate NAT gateways where multiple employees access accounts from same public IP
#   - Household devices shared among family members with separate accounts
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
