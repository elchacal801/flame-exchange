# ======================================================================
# FLAME Detection Rule: Credential Spray Single Password
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P2
# Threat Paths: TP-0013, TP-0001
#
# Description:
#   Detects password spraying attacks where a single password (or small set
#   of passwords) is tested across many accounts. Unlike traditional
#   credential stuffing which uses unique username-password pairs, password
#   spraying tries common or recently breached passwords against a large
#   account population to avoid per-account lockout thresholds.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: login_attempt
#     auth_result: failure
#   timeframe: 30m
#   condition: 'selection | count(distinct username) by password_hash > 20 and count(distinct
#     password_hash) by source_ip < 3
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Batch account creation workflows where a default password is assigned to many accounts
#   - Automated test frameworks using a shared test password across test accounts
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
