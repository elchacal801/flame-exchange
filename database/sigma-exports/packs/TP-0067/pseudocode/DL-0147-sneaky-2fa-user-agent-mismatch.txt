# ======================================================================
# FLAME Detection Rule: Sneaky 2FA Impossible Device Shift — User-Agent Mismatch per Auth Step
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: critical
# CFPF Phase: P2
# Threat Paths: TP-0067
#
# Description:
#   Detects the "impossible device shift" signature characteristic of
#   Sneaky 2FA and related AiTM phishing kits. Sneaky 2FA uses different
#   hardcoded User-Agent strings per authentication step — Safari on iOS
#   for the Login:login step and Edge on Windows for the Login:resume step.
#   This pattern is detectable via correlation of mismatched User-Agents
#   within the same correlation ID within 10 minutes. This detection also
#   catches Dadsec (missing User-Agent), Tycoon 2FA (rare User-Agent
#   values), and W3LL OV6 (inconsistent UAs).
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: azure
#   service: signinlogs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     ResultType: 0
#   condition: 'count(distinct UserAgent) by CorrelationId >= 2 AND timeframe < 10 minutes
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Extremely rare in legitimate authentication — different User-Agents within the same correlation ID should not occur in normal browser authentication
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
