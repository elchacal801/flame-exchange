# ======================================================================
# FLAME Detection Rule: Rockstar 2FA / FlowerStorm Application ID and User-Agent Detection
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: critical
# CFPF Phase: P2
# Threat Paths: TP-0067
#
# Description:
#   Detects sign-ins associated with the Rockstar 2FA and FlowerStorm AiTM
#   phishing kits (Storm-1575 lineage) by matching the hardcoded Office365
#   Application ID and User-Agent string used by these kits. Rockstar 2FA
#   and its successor FlowerStorm use the Office365 Application ID
#   72782ba9-4490-4f03-8d82-562370ea3566 combined with the hardcoded
#   User-Agent string containing "WebView/3.0" — a high-fidelity detection
#   signature with very low false positive rate. FlowerStorm surged within
#   ~10 days of Rockstar 2FA's infrastructure collapse in November 2024.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: azure
#   service: signinlogs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection_appid:
#     AppId: 72782ba9-4490-4f03-8d82-562370ea3566
#   selection_useragent:
#     UserAgent|contains: WebView/3.0
#   condition: selection_appid AND selection_useragent
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Very low — this specific Application ID and User-Agent combination is not used by legitimate Microsoft client applications
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
