# ======================================================================
# FLAME Detection Rule: AiTM Session Token Replay Detection — User-Agent and IP Mismatch Post-MFA
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P3
# Threat Paths: TP-0067, TP-0002
#
# Description:
#   Detects potential Adversary-in-the-Middle (AiTM) session token replay
#   by identifying User-Agent string or IP address mismatches between MFA
#   completion events and subsequent session access events. AiTM phishing
#   kits capture session tokens during MFA relay, then replay them from
#   attacker infrastructure with different User-Agent/IP characteristics.
#   Sekoia.io identified 11 major AiTM kits (Tycoon 2FA most prevalent:
#   1,200+ domains, 500K+ organizations/month). FIDO2 blocks 93.9% of AiTM
#   campaigns.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: azure
#   service: signinlogs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection_mfa:
#     AuthenticationRequirement: multiFactorAuthentication
#     ResultType: 0
#   timeframe: 4h
#   condition: 'session access from IP != MFA authentication IP OR session User-Agent
#     != MFA User-Agent
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Users switching between VPN and direct connection during authentication
#   - Mobile users with carrier IP changes between MFA and access
#   - Users authenticating via one device and accessing via another (legitimate SSO patterns)
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
