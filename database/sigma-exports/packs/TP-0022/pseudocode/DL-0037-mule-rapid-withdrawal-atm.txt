# ======================================================================
# FLAME Detection Rule: Mule Rapid ATM Withdrawal After Inbound Transfer
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P5
# Threat Paths: TP-0011, TP-0022, TP-0001
#
# Description:
#   Detects cash withdrawals at ATMs occurring shortly after an inbound
#   wire or ACH transfer. Money mules frequently convert electronically
#   received fraud proceeds to cash as quickly as possible to prevent
#   recovery, often hitting daily ATM limits across multiple machines.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: transaction_monitoring
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection_inbound:
#     event_type:
#     - WIRE_CREDIT
#     - ACH_CREDIT
#     transaction_amount|gte: 2000
#   selection_atm_withdrawal:
#     event_type: ATM_WITHDRAWAL
#     transaction_amount|gte: 500
#   timeframe: 4h
#   condition: selection_inbound | near selection_atm_withdrawal by account_id
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Small business owners depositing and immediately withdrawing cash for operational expenses
#   - Individuals receiving legitimate payroll via direct deposit and withdrawing cash
#

#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
