# ======================================================================
# FLAME Detection Rule: Gift Card Merge and Transfer Anomaly Detection
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P3
# Threat Paths: TP-0068
#
# Description:
#   Detects suspicious gift card merge and transfer activity indicating
#   value consolidation from multiple illicit sources. NRF RFT FT1202
#   documents that fraudsters transfer value from multiple illicitly
#   obtained gift cards to a single legitimate card — e.g., 20 cards with
#   $5 merged into one $255 card. This consolidation is a key Control phase
#   technique enabling subsequent monetization. Detection signals include
#   merge velocity, source card count, and correlation with recent
#   suspicious balance check activity.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: retail
#   service: gift_card_transactions
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     transaction_type:
#     - merge
#     - transfer
#     - consolidate
#   timeframe: 1h
#   condition: 'count(distinct source_card) by destination_card >= 3 AND timeframe < 60
#     minutes
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Corporate gift card consolidation during employee reward program administration
#   - Legitimate customer merging multiple small-value gift cards received as gifts
#   - Gift card balance cleanup during promotional campaigns
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
