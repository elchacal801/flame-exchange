# ======================================================================
# FLAME Detection Rule: Distributed Credential Stuffing
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: medium
# CFPF Phase: P2
# Threat Paths: TP-0013, TP-0001
#
# Description:
#   Detects low-and-slow distributed credential stuffing attacks spread
#   across multiple source IPs to evade per-IP rate limiting. Advanced
#   attackers use residential proxy networks and botnets to distribute
#   attempts, making each source IP appear benign while the aggregate
#   attack targets many accounts. This rule aggregates failed login
#   patterns across source IPs sharing common characteristics.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: login_attempt
#     auth_result: failure
#   selection_characteristics:
#     user_agent|re: ^Mozilla/5\.0.*$
#   timeframe: 30m
#   condition: 'selection and selection_characteristics | count(distinct source_ip) by
#     user_agent > 20 and count(distinct username) by user_agent > 50 and max(count()
#     by source_ip) < 5
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Large-scale legitimate user activity from a popular browser version during peak hours
#   - CDN or reverse-proxy traffic aggregation that normalizes user-agent strings
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
