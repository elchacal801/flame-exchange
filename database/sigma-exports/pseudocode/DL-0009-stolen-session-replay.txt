# ======================================================================
# FLAME Detection Rule: Stolen Session Token Replay
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: critical
# CFPF Phase: P2
# Threat Paths: TP-0008, TP-0001
#
# Description:
#   Detects session token replay from a different geographic location or
#   device than the original authenticating session. When infostealers
#   exfiltrate active session cookies, attackers import them into
#   antidetect browsers to hijack authenticated sessions without triggering
#   login-based detections. This rule correlates session token usage across
#   differing geolocations and device fingerprints.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: auth_logs
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: session_activity
#     session_token|exists: true
#   filter_same_context:
#     geo_country: '%original_session_country%'
#     device_fingerprint: '%original_device_fingerprint%'
#   condition: selection and not filter_same_context | count() by session_token > 1
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Users connecting via VPN whose egress IP changes geographic region mid-session
#   - Mobile users roaming internationally with active banking sessions
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
