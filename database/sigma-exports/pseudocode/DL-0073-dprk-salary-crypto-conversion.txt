# ======================================================================
# FLAME Detection Rule: Salary Direct Deposit Rapid Cryptocurrency Conversion
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: medium
# CFPF Phase: P5
# Threat Paths: TP-0034
#
# Description:
#   Detects patterns where salary direct deposit payments are rapidly
#   converted to cryptocurrency (USDT, USDC, BTC) within 48 hours of
#   deposit, particularly when the receiving account was recently opened or
#   when multiple employee accounts show the same conversion pattern
#   through the same exchange or payment processor. DPRK IT workers convert
#   salary to cryptocurrency for transfer to regime-controlled wallets,
#   often using daily conversion limits to avoid AML alerts.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: transaction_monitoring
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection_deposit:
#     transaction_type: ACH_IN
#     transaction_category: payroll
#   selection_conversion:
#     outbound_type|contains:
#     - crypto_exchange
#     - p2p_crypto
#     - wire_to_exchange
#     time_since_deposit_hours|lte: 48
#   condition: selection_deposit | near selection_conversion
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Employees who routinely invest a portion of salary in cryptocurrency through automated transfers
#   - Cryptocurrency industry employees whose compensation is partially crypto-denominated
#
# ======================================================================

#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
