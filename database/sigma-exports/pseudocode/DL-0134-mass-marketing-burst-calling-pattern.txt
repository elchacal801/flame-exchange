# ======================================================================
# FLAME Detection Rule: Mass-Marketing Fraud Burst Calling Pattern — SIM Farm and Robodialling Detection
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: medium
# CFPF Phase: P2
# Threat Paths: TP-0065
#
# Description:
#   Detects burst patterns from potential SIM farm or robodialling
#   infrastructure targeting customer phone numbers. Mass-marketing fraud
#   infrastructure uses sequential phone numbers, short call durations
#   (most calls rejected), and high-volume outbound calling to reach
#   victims at scale. This rule identifies inbound calling patterns
#   characteristic of organized boiler room operations, including
#   sequential source number prefixes, short call duration clustering, and
#   geographic origin mismatch between caller ID display and actual call
#   routing.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: telecom
#   service: cdr
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     call_direction: inbound
#   timeframe: 1h
#   condition: selection | count(distinct destination_number) by source_number_prefix
#     > 50 AND selection | avg(call_duration) by source_number_prefix < 30
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Legitimate telemarketing campaigns from licensed call centers
#   - Automated notification systems (bank alerts, appointment reminders)
#   - Political campaign robodialling during election periods
#
# ======================================================================

#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
