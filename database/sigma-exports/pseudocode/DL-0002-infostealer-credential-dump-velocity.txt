# ======================================================================
# FLAME Detection Rule: Infostealer Credential Dump Velocity
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P2
# Threat Paths: TP-0001, TP-0023
#
# Description:
#   Detects rapid credential dump patterns where many unique credentials
#   are harvested from a single host in a short timeframe. Infostealers
#   such as RedLine, Lumma, and Vidar typically exfiltrate dozens to
#   hundreds of stored credentials within seconds of execution, producing a
#   burst of credential-access events from one endpoint.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: endpoint_detection
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: credential_access
#     action: credential_read
#   filter_legitimate:
#     process_name|endswith:
#     - \lsass.exe
#     - \services.exe
#   timeframe: 5m
#   condition: selection and not filter_legitimate | count(distinct target_credential)
#     by host_id > 20
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Legitimate credential manager software performing bulk synchronization
#   - Enterprise password vault agents rotating stored credentials
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
