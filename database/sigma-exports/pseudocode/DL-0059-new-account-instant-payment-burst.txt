# ======================================================================
# FLAME Detection Rule: New Account Sending Multiple Instant Payments
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P5
# Threat Paths: TP-0024
#
# Description:
#   Detects accounts less than 30 days old that initiate multiple instant
#   payments within a short time window. Newly opened accounts used for
#   rapid instant-payment disbursement are a strong indicator of synthetic
#   identity fraud or mule accounts created specifically for the
#   monetization phase of a fraud scheme.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: instant_payments
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     event_type: instant_payment_initiated
#     payment_rail|contains:
#     - ZELLE
#     - FEDNOW
#     - RTP
#     - ACH_SAMEDAY
#   filter_new_account:
#     account_age_days|lt: 30
#   condition: selection and filter_new_account | count() by account_id > 5
#   timeframe: 48h
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Newly opened business account setting up recurring vendor payments
#   - College student opening account and paying multiple roommates for shared expenses
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
