# ======================================================================
# FLAME Detection Rule: Long-Firm Credit Buildup Pattern — Steady Low Utilization Followed by Rapid Spike
# ======================================================================
#
# This rule uses aggregation/correlation logic that requires
# SIEM-native implementation. It cannot be auto-converted to
# SPL/Lucene/KQL by pySigma backends.
#
# Level: high
# CFPF Phase: P4
# Threat Paths: TP-0064
#
# Description:
#   Detects commercial accounts following a long-firm fraud pattern: steady
#   low-value credit utilization for 6-12 months (building
#   creditworthiness) followed by rapid escalation in credit utilization
#   (the "burst"). Long-firm fraud involves organized criminal groups
#   establishing businesses, building credit relationships, then exploiting
#   that trust to defraud supply chain partners and trade finance banks.
#   The artificially smooth buildup period followed by a discontinuous
#   spike is the hallmark behavioral indicator.
#
# ----------------------------------------------------------------------
# Log Source
# ----------------------------------------------------------------------
#   product: banking
#   service: commercial_credit
#
# ----------------------------------------------------------------------
# Detection Logic (Sigma YAML)
# ----------------------------------------------------------------------
#   selection:
#     account_type: commercial
#   timeframe: 12m
#   condition: 'trailing_6m_avg_utilization < 35% AND current_month_utilization > 80%
#     AND prev_month_utilization < 50%
#   
#     '
#
# ----------------------------------------------------------------------
# Known False Positives
# ----------------------------------------------------------------------
#   - Seasonal businesses with legitimate cyclical credit utilization spikes
#   - Businesses undergoing genuine rapid growth requiring increased credit
#   - One-time large purchase on established credit facility
#
# ======================================================================
# Implementation Notes:
#   - Review the condition syntax and implement using your SIEM's
#     native aggregation/correlation capabilities
#   - Splunk: Use 'stats' or 'transaction' commands
#   - Elastic: Use EQL sequences or aggregation queries
#   - Sentinel: Use KQL summarize/make-series operators
# ======================================================================
